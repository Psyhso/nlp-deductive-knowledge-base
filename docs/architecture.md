# Архитектура

## Пайплайн

1. Пользователь вводит текст с исходными утверждениями.
2. Сервер делает один запрос к LLM через OpenAI-совместимый API.
3. Модель возвращает JSON. Python проверяет структуру, ссылки, типы, область переменных и наличие цитат в исходном тексте.
4. Пользователь просматривает перевод и при необходимости выбирает предложенные определения.
5. Локальный движок проверяет базу и находит новые факты.
6. Интерфейс показывает исходные и новые факты отдельно, с основаниями вывода и признаками неполного поиска.

## Общий режим

`web/general_llm.py` формализует текст по `prompts/formalization.txt`. Верхний уровень JSON содержит `version`, `sorts`, `predicates`, `entities`, `premises`, `proposals`, `queries`, `unparsed`.

Термы ссылаются только на объявленный объект или связанную переменную. Формулы задаются деревом с операциями `atom`, `not`, `and`, `or`, `implies`, `iff`, `forall`, `exists`, `eq`, `true`, `false`. Строки кода не исполняются.

Цитаты в `premises[].evidence`, `entities[].mentions` и `unparsed[].text` проверяются как непрерывные подстроки после нормализации Unicode (NFC), регистра, пробельных символов и типографических вариантов кавычек и тире. Например, перенос между «прочитал» и «книгу месяца» не мешает принять цитату одной строкой. Слова, их порядок, отрицания, числа и остальная пунктуация должны сохраняться; нечёткий поиск и автоматическое исправление пересказов не используются. В возвращаемом JSON остаётся исходное написание цитаты. Такая проверка подтверждает наличие фрагмента в источнике, но сама по себе не доказывает правильность перевода в формулу.

`web/logic_engine.py` проверяет пакет и компилирует его в отдельный Z3 Context. В базу входят исходные посылки и явно принятые предложения. После проверки согласованности движок перебирает ground-атомы объявленных предикатов на известных именованных объектах подходящего типа. Массив `queries` может быть пустым.

Следствие `A` проверяется через несовместность `S ∧ ¬A`. Его отрицание проверяется через несовместность `S ∧ A`. Если оба варианта выполнимы, база не определяет истинность `A`. `unknown` и достижение лимита обозначают незавершённую проверку, а не ложность.

Основания общего вывода — идентификаторы достаточных посылок из unsat core. Это не обязательно минимальное ядро или пошаговое дерево доказательства.

## Профильный режим

В `data/profiles` лежат словари, правила и примеры для базовых зависимостей курсов, университетской области и семейных отношений. LLM извлекает ground-факты из фиксированного словаря. Модули `datalog` загружают их в неизменяемые Python-объекты, выполняют полунаивный вывод и возвращают объяснения через правило, подстановку, родителей и номер раунда.

## Веб-слой

Основные маршруты:

| Маршрут | Назначение |
|---|---|
| `GET /api/general/bootstrap` | Настройки интерфейса и список примеров |
| `POST /api/general/extract` | Один запрос к LLM, без логического анализа |
| `POST /api/general/analyze` | Локальная проверка JSON и вывод |
| `POST /api/general/demo` | Готовый пример без LLM |
| `/api/bootstrap`, `/api/extract`, `/api/analyze`, `/api/infer`, `/api/demo` | API Datalog-профилей |

Статический интерфейс состоит из HTML/CSS/JavaScript и не требует отдельной сборки. Результат живёт в памяти страницы. Приложение предназначено для локального учебного запуска и по умолчанию слушает `127.0.0.1`.
